# 이대리 자동 리뷰 봇 응답 규약 (이 레포 전용)

이대리 봇은 **자기 리뷰의 채택/기각을 학습**한다. 그래서 답변만으로 끝내지 않고 **정탐/오탐 판정을 이모지로 남기는 것이
필수**다. 이모지가 학습 신호의 결정론적 입력이고, 답변 텍스트가 기각 이유(학습 재료)다.
(수집·평가·triage·인라인 답변 등 공통 절차는 `~/.claude/CLAUDE.md` §「PR 봇 리뷰 대응」)

- **식별**: 코멘트 본문이 `🤖 **이대리 자동 리뷰**` 로 시작하는 인라인 코멘트. 봇이 owner PAT로 달아서
  **작성자 계정이 사람과 같다** — 계정으로 구분하려 하지 말고 이 표식으로 판별한다.
- **정탐 → 👍**
  `gh api --method POST repos/<owner>/<repo>/pulls/comments/<comment_id>/reactions -f content=+1`
  - **지적은 맞지만 이번 PR 에서 고치지 않는 경우도 👍 다**(범위 밖·의도된 위험 수용·후속으로 미룸).
    👎 의 기준은 "이 PR 에서 안 고친다" 가 아니라 "지적 자체가 틀렸다" 다. 미룬 이유는 답글로 남긴다.
    👎 를 달면 그 답글이 레포 규약 재료가 되어 같은 종류의 맞는 지적을 억제한다(SECURITY 는
    `NEVER_LEARNED_CATEGORIES` 라 규약에 실리지 않지만 채택률은 왜곡된다).
  - 답글만 단 카드는 마지막 답글 10분 뒤에야 LLM 판정으로 넘어간다(`REPLY_JUDGE_GRACE_MS`) — 답글 직후
    단 이모지가 판정기보다 먼저 읽히게 하려는 유예다. 이 유예가 없던 동안 「맞습니다, 다만…」 답글이 👍 보다
    먼저 판정돼 기각된 카드가 있었다(#1679·#1724).
- **오탐(부정확·반박) → 반박 근거를 인라인 답변으로 먼저 게시하고, 그 다음 👎**
  `... /reactions -f content=-1` (REST 값은 `+1`/`-1`)
  🔴 **순서를 지킨다.** `harvest-signal.ts:106-134` 는 리액션을 답글보다 먼저 보고 `REJECTED` 를 낸다.
  👎 만 있고 owner 답글이 없으면 수확은 24시간(`REJECTION_REPLY_GRACE_MS`) 기다렸다가, 그래도 없으면
  `rejectReason: null` 로 확정하고 카드를 닫는다(`harvest-review-signals.usecase.ts:417-430`, #527).
  유예 덕에 👎 를 먼저 달아도 하루 안에 **owner** 가 답글을 달면 이유가 수확되지만, PR 작성자 등 다른 계정의 답글은
  유예를 끝내지도 이유로 쓰이지도 않고, 하루 뒤에 단 답변은 영영 수확되지 않는다.
  이유 없는 기각은 학습 재료로서 가치가 없으니 답변을 먼저 단다.
- **멘션은 불필요**(봇이 폴링 스윕으로 읽는다). 외부 봇용 멘션 규칙은 이 봇에 적용되지 않는다.
- **답변 본문을 `🤖 **이대리 자동 리뷰**` 로 시작하지 않는다** — 표식으로 시작하면 봇이 자기 글로 걸러내
  답변이 신호에서 빠진다(`harvest-signal.ts:91`).
- **owner 와 PR 작성자의 리액션만 신호로 인정**된다(`harvest-signal.ts:107-111`, 인정 계정은
  `harvest-review-signals.usecase.ts:279-284`). 그 밖의 계정의 👍👎는 무시된다. 기각 이유(규약 재료)는 owner 답글만 쓴다.
- 이모지가 없으면 답글을 LLM(`REVIEW_REPLY_JUDGE`)이 배치 판정한다(`harvest-signal.ts:136-144`) — 이모지를 남기면
  그 LLM 호출과 오판 가능성을 건너뛴다. 이게 이모지를 요구하는 실질적 이유.
- 🔴 **정탐에 👎 금지**: `REJECTED` 카드의 기각 이유는 그 레포의 **규약**이 되어 다음 리뷰
  프롬프트에 실린다(`learned-conventions.ts` — 카테고리당 기각 2건·이유 40자 이상). 정탐을 기각하면 "이 레포에서는
  그게 정상" 이라고 가르치는 셈이라 좋은 지적을 피하도록 **역학습**한다. 반대로 오탐에 👍를 누르면 채택률이
  부풀려져 억제 게이트가 잘못 학습한다. **판정은 실제 코드 근거로만** (맹종·맹반 금지).
  (기각 카드를 episodic memory 에 쌓던 옛 경로는 읽는 곳이 사라져 제거됐다 — 규약이 유일한 학습 경로다.)
- **잘못 누른 👎 되돌리기**: `pnpm review:unlearn <카드id>` 로 미리보기, `--apply` 로 적용. 카드를 `ACKED` 로
  바로잡아 규약 재료에서 빼고 채택률도 제 값으로 돌린다. `--apply` 를 빼면 아무것도 바꾸지 않고 "뺀 뒤의 규약
  블록" 을 보여준다. 카드 id 는 GitHub 코멘트 id 가 아니라 `pr_review_finding.id` 다
  (`select id, pull_number, category, decided_at from pr_review_finding where status = 'REJECTED'`).
  이미 나간 리뷰는 되돌리지 못하므로 예방이 먼저다. GitHub 의 👎 리액션은 손으로 지운다.
- 이모지 부착도 게시와 같은 outward 액션 → **승인 게이트 적용**(무엇에 👍/👎를 달지 + 답변 초안을 먼저 보고).
