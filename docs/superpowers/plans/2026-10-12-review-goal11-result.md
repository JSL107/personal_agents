# 목표 11 결과 — 보인 결함을 테스트 공백으로 돌리지 않게 하는 프롬프트 변경 (2026-10-12)

> 날짜 스냅샷이다. 이후 갱신하지 않는다. 원장: `tasks/goals-pr-review-loop.md` 「목표 11」.

## 한 줄 결론

missingTests 규칙에 "diff 안에서 입력 → 결과를 따라가 틀린 동작이 나오면 결함으로 쓴다"는 조건을 넣어 변경 전·후를
3회씩 재생했다. 결함 쪽으로 옮겨 가는 움직임(테스트 공백 지적 106 → 67건, 미탐 3건 개선)은 보였지만 효과 크기가
회차 변동 범위 안이었고, 목표가 대표 사례로 든 `v5#1062` 에서는 오히려 테스트 공백 카드로 후퇴한 회차가 늘었다.
**효과 없음 또는 측정 불가로 판정하고 프롬프트 변경은 철회했다.** 이 문서는 측정 결과와 시험한 문장만 남긴다.

## 1. 가설 확인 — 무엇이 후퇴를 일으키나

모델 호출 없이 2026-10-01 공식 기준선(`2026-10-01-official-baseline-v2-anchored-t3-17087f77.json`)의 모델 출력과
원장 카드 4장을 다시 읽었다.

- 원장 카드 4장 중 3장이 근거로 PR 본문의 "미확인" 문구를 든다. 647 "PR 본문에서 실제 Docker build가 실행되지
  않았다고 밝혔으므로 … 미확인이다", 664 "PR 본문도 깨진 롤아웃에서 CI가 실패하는 동작은 미확인이라고 명시한다",
  775 "창별 scanned 결과도 PR 본문상 미확인입니다". 코드를 따라가기 전에 작성자가 적은 미검증 목록을 테스트
  공백 카드로 옮기는 습관이 시스템 프롬프트 31행 문장보다 직접적인 방아쇠로 보인다.
- 그런데 4건 중 `v5#1058`·`v5#1082` 는 10-01 기준선에서 이미 MUST_FIX 로 잡히고 있었다(3/3, 2/3). 이 글을 쓰는
  날의 변경 전 실행에서는 `v4#270`·`v5#1062` 도 3/3 잡았다. 목표가 처음 짚은 4건은 지금 main 에서 대부분
  해소돼 있었다.
- 남아 있던 후퇴 사례는 `v4#277`(3회 중 2회가 "재삽입 시 속성 보존 테스트 없음")과 `v5#1082` 1회였다. 둘 다 PR
  본문의 미검증 문구를 인용한다.

## 2. 시험한 변경

`src/agent/code-reviewer/domain/prompt/code-reviewer-system.prompt.ts` 31행의 missingTests 문장 뒤에 아래를 붙였다
(새 줄을 덧붙이지 않고 같은 문장을 치환). 부재 근거 금지·의도 주석 반박 규칙은 오탐 방지용이라 건드리지 않았다.

> 단 그 시나리오를 diff · [related code] 안에서 입력 → 분기 → 결과로 끝까지 따라가 틀린 동작(예외, 잘못된 값,
> 실패가 성공으로 처리됨)이 나오면 그것은 추정이 아니라 관찰한 결함이다 — missingTests 가 아니라 mustFix 로 쓰고,
> 따라간 경로를 근거로 적는다. PR 본문이 "미검증 · 미확인" 이라고 적은 항목도 먼저 코드로 따라가 보고, 틀린
> 동작이 안 나올 때만 missingTests 로 쓴다.

변경을 적용한 상태에서 `pnpm lint:check`·`pnpm test`(7002 + 45)·`pnpm build`·`check:di`·`pnpm test:e2e`(12)는
모두 통과했다. 프롬프트 문구를 고정하는 테스트는 이 레포에 없다.

## 3. 측정 방법

- 표본: 미탐 13건(목표 6 앵커 파일 중 10-01 기준선에서 diff 가 잘리지 않은 것) + 짝 PR 의 놓친 쪽 3건(`v4#282`,
  `v4#270`, `v5#1062`) + 정탐 대조군 12건(목표 6 에서 이대리가 잡은 12건) = 28건 27그룹, 그리고 REJECTED 카드
  10장(공식 기준선과 같은 id). 짝 PR 과 대조군은 외부 리뷰 코멘트의 `original_commit_id`·`original_line`·원문으로
  앵커 파일을 새로 만들었다(`docs/superpowers/audits/replay/misses-2026-10-12-goal11.json`, 회사 위치가 담겨
  커밋하지 않는다).
- 표본 규모는 쿼터 때문에 줄였다. 120K 로도 지적 줄이 입력 밖인 미탐, diff 가 잘리던 미탐, FIXED 10장은 뺐다.
  목표 6 의 재리뷰 대상 27개 전체가 아니라 그중 프롬프트 변경이 움직일 수 있는 16건만 쟀다는 뜻이다.
- 실행: 같은 명령을 변경 전(`origin/main` `49c82355`)과 변경 후로 두 번, `--trials 3 --holdout`. 변경 후 실행에는
  변경 전 보고서를 `--baseline` 으로 붙였다. 재생은 `publish` 를 넘기지 않아 게시 경로를 타지 않는다.
- 보고서: `2026-10-12-goal11-before-49c82355-t3.json`, `2026-10-12-goal11-after-t3.json` (+ `.log`, `.json.stdout`).
- 판정: 채점기(v2) 값과 별도로, 원장 `agent_run.output` 의 같은 파일 지적을 외부 리뷰 원문과 한 건씩 대조해

## 5. 해석

- 변경은 의도한 방향으로 작동하기는 했다. 테스트 공백 지적이 크게 줄었고, `v4#264`·`v4#277`·`v5#1147` 에서는
  "테스트가 없다"던 자리가 입력 → 결과를 따라간 결함 지적으로 바뀌었다.
- 그러나 같은 규칙이 `v5#1062`·`v5#1063` 에서는 반대로 작용했다. 변경 후 이 두 PR 의 회차 일부는 apply 실패
  무시를 짚지 않고 롤아웃 실패 경로를 테스트 공백으로만 냈다. 새 문장의 "PR 본문이 미확인이라고 적은 항목은
  코드로 따라가 본다"가 작성자가 미확인이라 적은 지점(롤아웃 실패)으로 시선을 모아, 그 옆의 진짜 결함(apply)을
  덜 보게 만든 것으로 추정한다. 2개 PR × 3회라 회차 변동일 가능성도 배제하지 못한다.
- 목표가 처음 든 4건은 이미 지금 main 에서 대부분 잡힌다. 프롬프트 변경으로 움직일 수 있는 남은 몫이 작다
  (16건 중 늘 놓치는 7건은 도메인 지식·diff 밖 코드 문제).

## 6. 판정과 남는 것

- **철회.** 개선이라는 근거가 없고, 대표 사례에서 후퇴가 늘어난 변경을 운영 리뷰에 넣지 않는다. 철회 조건
  ("새로 잡은 것이 0인데 지적만 늘었다")에 정확히 걸린 것은 아니다 — 지적은 줄었고 새로 잡은 것이 1건 있다.
  효과가 회차 변동 안이라 판정 불가로 닫는 것이다.
- 이 표본으로 20%p 미만의 효과는 가려낼 수 없다(재생 계획 §8-3 과 같은 한계). 다시 시도한다면 PR 본문의
  "미확인" 문구를 결함 탐색의 출발점으로 삼게 하는 문장은 빼고, 입력 → 결과 추적 조건만 남겨 재는 것이 다음
  후보다.
- 채점기 v2 는 이번에도 양방향으로 틀렸다. 16건 × 3회 × 두 실행(96칸) 중 잘못 셈 11칸, 놓침 7칸이다. 잘못 셈에는 테스트 공백 카드를 결함 재현으로 센 칸(`v5#1062` 후 t1·t2, `v5#1082` 전 t1)이 들어 있어, 채점기 숫자만 보면 이번 목표가 겨냥한 후퇴 자체가 보이지 않는다. 카드 단위 판단에는 본문 대조가
  여전히 필요하다.
- 측정하지 않은 것: 목표 6 재리뷰 대상 중 diff 가 잘리던 미탐 12건, FIXED 카드 10장, REJECTED 재현의 본문 대조.
