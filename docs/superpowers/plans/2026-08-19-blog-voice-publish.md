# 초안을 내 말투의 글로 바꿔 발행하기 — 편집·말투 두 단계 신설

작성일 2026-08-19 · 대상 `feat/blog-voice-publish`

## 무엇이 문제였나

Notion 초안을 GitHub 블로그로 발행하는 경로는 이미 있었다(익명화 → Astro 포스트 → 승인 카드 →
커밋). 그런데 발행되는 글이 **초안 그대로**였다. 실제로 확인해 보니 두 가지가 드러났다.

- 발행본 첫머리에 `> 제목 후보: A|B|C` 같은 초안 워킹 노트가 그대로 남아 공개 저장소로 나갈 상태였다.
- 문체가 이대리 보고서체였다. 사용자 명의로 공개되는 글인데 목소리가 사용자의 것이 아니다.
  이대리의 윤문 프롬프트는 `문어체 보고의 격은 유지하라(구어 반말·과한 입말 금지)` 를 명시하고 있었다.

말투의 실측 프로파일은 이미 있었다(문장 길이 편차 13.7, 20자 이하 문장 26.1%, 구어 어미 16.5%,
금지 접속사 0회 — 소개 글 본문 115문장 기준). 다만 그 문서는 Claude Code 스킬 쪽에 있고 이대리
서버에는 없었다.

## 어떻게 바꿨나

발행 경로에 두 단계를 넣었다.

```
Notion 초안(가장 오래된 1건)
  ├─ 열린 발행 카드가 있으면 이번 회차는 넘김
  ├─ 익명화        식별정보 제거            (기존)
  ├─ 편집          요지 잡고 추려내기        (신설)
  ├─ 말투          문단만 개인 문체로 윤문   (신설)
  ├─ 금지어 검사   파이프라인 끝에서 한 번   (순서 변경)
  └─ 카드 → 승인 → GitHub 커밋 + Notion '발행'
```

세 단계를 한 번의 모델 호출로 합치지 않았다. 계약이 상반되기 때문이다 — 익명화는 치환, 편집은
덜어내기, 말투는 한 글자도 빼지 않기. 한 프롬프트에 섞으면 모델이 어느 쪽을 지키는지 흐려지고
실패 지점도 짚을 수 없다.

### 편집 단계

이 글이 말하려는 것 한 문장을 먼저 정하고, 거기에 기여하지 않는 대목을 덜어낸다. 초안 워킹 노트,
중복 문단, 목차성 장치가 제거 대상이다. 코드블록·수치·기술적 결론은 건드리지 않는다.

산출물은 `publishable` · `reason` · `title` · `slug` · `description` · `body` 다. 제목을 다듬으면
같은 단계에서 주소(slug)도 함께 만든다. 제목과 URL 이 어긋난 채 영구히 박히는 것을 막기 위해서다.

발행할 만한 글이 아니라고 판정하면(필기 수준, 요지 없음, 800자 미만, 틀린 내용 중심) Notion 상태를
**보류**로 옮긴다. 이게 없으면 같은 초안이 매일 다시 뽑혀 뒤에 있는 초안이 영구히 발행되지 않는다 —
선택 로직이 "가장 오래된 1건" 고정이기 때문이다.

과삭제 방지로 편집본이 원문의 60% 미만이면 실패로 끊는다.

### 말투 단계

마크다운을 산문 문단과 보존 블록(코드·표·헤딩·인용·목록)으로 가른 뒤 문단만 윤문한다. 블록을
문자열로 복사하지 않고 줄 번호 구간으로 가리키므로, 윤문 결과가 원문과 같으면 재조립 결과도 원문과
한 글자도 다르지 않다.

`HumanizeService` 에 `voice: 'personal-blog'` 를 추가했다. 프롬프트는 보고체 지시 한 줄을 **치환**해서
만든다. 덧붙이기만 하면 상충하는 앞 지시가 이겨 새 지시가 먹지 않는다.

### 함께 고친 것

- **발행 날짜가 초안 작성일이었다.** 6월 초안을 8월에 승인해도 6월 글로 발행돼 최신순 목록 아래에
  묻혔다. 승인해서 커밋하는 날로 바꿨다.
- **미응답 카드 중복.** 어제 카드를 두면 오늘 또 모델 세 번을 태우고 같은 글 카드가 두 장 떴다.
  열린 카드가 있으면 그 회차를 넘긴다.
- **파싱 실패의 근거가 어디에도 없었다.** 이 파이프라인의 첫 실행(run#864)이 익명화 응답 파싱에서
  죽었는데, 모델이 무엇을 돌려줬는지 로그·원장 어디에도 남지 않았다. 원인은 공용 JSON 추출기가
  JSON 문자열 값 안의 코드펜스를 응답 펜스로 오인한 것이었다. 추출기를 "실제로 파싱되는 후보를
  고르는" 방식으로 바꾸고, 실패 로그에 모델 응답 앞부분이 남도록 했다.

## 아직 하지 않은 것

- **문체 지표를 차단 게이트로 쓰지 않는다.** 카드에 수치만 적는다. 임계값은 발행본이 몇 편 쌓여
  분포가 보인 뒤에 정할 일이다.
- **카드를 만든 날과 승인한 날이 다르면 경로 날짜가 하루 어긋난다.** 카드 수명이 24시간이라 최대
  하루이고, 없애려면 승인 시점에 경로를 다시 계산하는 구조가 필요하다.
- **여러 초안을 묶어 한 편으로 만드는 것**은 범위 밖이다. 이번 편집은 한 초안 안에서만 추린다.
- 승인 후 되돌리기는 GitHub revert 는 되지만 Notion 상태는 수동 복구다.
