# 목표 9 결과 — 변경 파일의 기존 테스트 본문을 리뷰 입력에 싣기 (2026-10-13)

> 날짜 스냅샷이다. 이후 갱신하지 않는다. 원장: `tasks/goals-pr-review-loop.md` 「목표 9」. 설계:
> `docs/superpowers/specs/2026-09-08-pr-review-depth-and-learning-design.md` §4 2단계.

## 한 줄 결론

변경 파일의 짝 테스트 본문을 `[기존 테스트]` 블록으로 리뷰 입력에 붙였다. 겨냥한 오탐("기존 테스트가 이미 덮고 있는데
'검증 안 됨'으로 지적")은 **변경 전 main 에서도 이미 재현되지 않아** 효과는 측정할 수 없었다. 정탐 대조군은 회차 변동
범위 안에서 유지됐고, 블록을 근거로 지적을 거둔 흔적은 없었다. 비용은 조회 1초 안팎과 프롬프트 최대 +58KB 이고 응답 시간은
늘지 않았다. **변경은 유지한다.**

`X*Test.php` 이고, 이름이 겹치면 가장 긴 소스가 가져간다. 트리 한 번 대조에 5ms 이하가 든다.

### 1-2. 선택 순서

스펙의 「MUST_FIX 후보가 걸린 파일 우선」은 리뷰 전에는 알 수 없어 뺐다. 짝 소스(또는 변경된 spec 자신)의 diff 변경 줄 수가
큰 순으로, 예산 60KB · 20개 안에서 고르고 넘친 것은 블록 머리에 경로와 함께 "N개 생략"으로 적는다.

## 2. 변경

- 포트 `listTree({ repo, ref })` 를 추가했다(octokit `git.getTree`, `recursive: 'true'`). 파일만 경로·크기로 돌려주고
  `truncated` 를 함께 준다.
- `src/agent/code-reviewer/domain/companion-spec.ts`: 짝 판정, 선택, 줄 번호를 붙인 조립. 상수(예산 60KB, 20개, 10초, 동시
  조회 4)는 이 파일 한 곳에 있고 프롬프트 안내 문구가 그 상수를 읽는다.
- `review-pull-request.usecase.ts`: 모든 레포에서 트리 1회 + 고른 파일만 조회해 블록을 만든다. 트리 전문은 싣지 않는다.
  `changedFilesTruncated` 면 "일부만 확인함", 트리가 잘렸으면 그 사실을 적고 짝 후보 경로를 추측해 개별 조회한다. 조회 실패·시간
  초과는 블록 없이(또는 모은 데까지) 진행한다. 블록은 `[related code]` 와 같은 신뢰 경계로 감싸고, 파일 경로가 담긴 안내도
  경계 안에 둔다. 블록에 실린 테스트는 `[related code]` 에서 다시 읽지 않는다.
- 시스템 프롬프트: 보수 규칙 문장은 그대로 두고, 근거로 인정하는 입력 목록("diff · [related code]")에 `[기존 테스트]` 를 넣었다.
  블록 설명 한 단락("missingTests 를 쓰기 전에 여기 이미 있는지 먼저 찾는다 · 블록에 없는 파일은 '안 실었다'일 수 있다")을
  더했다. 목록에서 빠지면 #714 때처럼 규칙이 새 맥락을 근거에서 배제한다.
- 재생 스크립트에 옵트인 `--full-file-list` 를 더했다. 기본은 잘린 diff 에서 변경 파일 목록을 다시 세는데, 운영은 API 가 전체
  목록을 준다. 기본값을 바꾸면 이전 보고서와 입력이 달라지므로 플래그로만 둔다.

## 5. 판정과 남는 것

- **변경 유지.** 겨냥한 효과는 표본에서 바닥에 붙어 측정할 수 없었다. 대신 정탐 후퇴가 보이지 않았고, 모델이 블록을 실제로
  근거로 쓰며(spec 인용 1 → 14건), 시간 비용은 제약 B 안이다. 목표 11 은 대표 사례에서 후퇴가 보여 철회했지만, 이번에는 그런
  후퇴가 없다.
- 🔴 **선택 규칙의 한계 (후속).** diff 가 잘린 PR 은 잘린 파일의 변경 줄 수를 0 으로 세서 선택 순서가 경로순으로 무너진다. 블록이
  가장 필요한 큰 PR 에서 약하다. 파일별 증감은 `pulls.listFiles` 응답에 이미 있으니(`getPullRequest` 가 같은 API 를 페이지네이션
  한다) 그 값을 `PullRequestDetail` 로 넘기는 것이 다음 후보다.
- **diff 절단 순서 (후속 후보, 이 목표 밖).** #412 처럼 문서 파일이 상한을 다 차지하면 소스가 입력에서 빠진다. 지금은 테스트만
  뒤로 미룬다(`octokit-github.client.ts` `truncateDiff`). 문서·계획 파일도 뒤로 미룰지 따로 잴 만하다.
- 측정하지 않은 것: 효과를 보일 수 있는 표본(이 유형 오탐이 지금 main 에서 재현되는 PR)은 찾지 못했다. 운영 로그(`기존 테스트 첨부`
  줄)로 실입력 바이트와 소요를 며칠 모아 예산 60KB 를 재조정하는 일은 배포 뒤로 남긴다.
