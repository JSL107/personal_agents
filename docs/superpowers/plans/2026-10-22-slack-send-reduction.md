## 2. "평일 채널 메시지"에 세는 것

**대표가 받는 메시지 전부**를 센다 — 메인 채널, 본인 DM, 투자 채널, 백엔드 공고 채널의 본문(top-level SENT, `slack_delivery`). 세지 않는 것:

- 다른 사람에게 가는 것 — 원화 공고 채널(`ART_JOB_FEED_TARGET`, 받는 사람 멘션)과 다른 사람의 사주·마감 DM.
- 주간 발송 — 주간 요약, 모의투자 주간 채점, 임팩트 리포트, 이력서 보정(월), 블로그 수정률.
- 댓글(스레드). `logs/slack-send.jsonl` 로 셀 때는 `push`·`card` 만 세고 `push-thread`·`card-thread` 는 뺀다.

jsonl 은 수신처가 없고 이미지가 붙은 발송(원화 공고)을 남기지 않는다. 원장(`slack_delivery`)은 #815 이전(10-13까지) 승인 카드를 남기지 않는다. 한쪽만으로 세면 어느 한쪽이 빠진다.

## 3. 변경 — 하루 3통이 줄어든다

| 무엇 | 바뀌는 것 |
|---|---|
| 승인 카드 | 따로 채널에 내지 않고 그 회차 본문(저녁 마감)의 댓글로 단다. 본문 끝에 "✋ 승인 카드 N장 — 이 메시지 댓글에 있습니다" |
| 정오 PO 검토 | 그날 아침 메시지의 댓글로 단다. 아침 본문을 못 찾으면 종전대로 채널 본문 |
| 장애 해결 알림 | DM 으로 보내지 않는다. 다음 아침 메시지에 "✅ 해결" 한 줄. 전문은 원장(콘솔)에 남는다 |
| 아침 첫 줄 | 급한 순서(장애 → 승인 → 공고)로 적고 맨 앞 종류는 이름까지. 예: `☀️ 10/21(수) 아침 — 🔴 장애: 블로그 GitHub 발행 실패 · ✋ 승인 2` |

본인 사주 DM 은 그대로 둔다(합칠 이유가 통수 1통뿐이라서). 원화 공고 하루 2회는 받는 사람의 일이라 이번 범위에서 뺐다.

지난 8일에 적용하면 평일 통수는 13·9·6·14·11·5·8·8 → 9·5·2·9·5·4·5·3, 평균 9.2 → 5.2통, 6통 이하인 날 2 → 6일이다. 남는 2일(10-12, 10-15)은 투자 채널 숨김 처리 전과 장애 3건이 난 날이다.

## 4. 승인 카드 처리율 — 부재 기간은 뺀다

10-17~10-20 동안 대표의 Slack 활동(멘션 실행·카드 승인)이 0건이었다(부재 확인). 10-19(월) 아침에는 카드 3장이 살아 있었고 첫 줄에 "승인 3"도 떴지만 눌리지 않았다. 그러므로 만료를 월요일 정오까지 늘리거나 월요일 아침에 다시 보여 주는 대책은 이 기간에 효과가 없다(2주 기준 최대 +2장).

**처리율은 "카드 생성 다음 날 대표의 Slack 활동이 없던 카드"를 빼고 센다.** 이렇게 세면 10-12~20은 16/16 = 100%, 10-08~21은 32/34 = 94.1%다. 만료된 후보는 대체로 다시 올라온다(예: 10-09에 만료된 크롤러 글이 10-11에 다시 제안돼 승인).

## 5. 위험과 후속

- **카드가 댓글로 숨는다.** 지금은 저녁에 받고 0~40분 안에 누른다. 처리율 ②가 떨어지면 되돌린다. 저녁 스레드에는 상세 댓글이 먼저 달리므로 카드는 스레드 아래쪽에 있다.
- **정오 PO 가 매일 나간다.** "계획과 어긋날 때만" 나가는 설계인데 10일 동안 10번 나갔다. 머지 없이 닫힌 PR(#3922)이 `FINDING_ABANDONED`("항상 켠다", `plan-reality.diff.ts`)로 10-17~20 매일 다시 지적된 것이 한 원인으로 보인다(추정, 미확인). 댓글로 옮겨 통수는 줄었지만 판정 기준은 따로 볼 일이다.
- 10-20 본인 사주가 09:00 과 09:40 에 서로 다른 형식으로 두 번 나갔다. 원인 미확인.
