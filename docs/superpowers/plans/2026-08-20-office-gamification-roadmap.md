# 오피스 게이미피케이션 로드맵 — 3회차

작성 2026-08-20. 회차마다 "이번에 안 하는 것"을 다시 논의하지 않기 위해 순서와 경계를 미리 박는다.
개별 회차의 상세 설계는 각 회차 스펙 문서에 있고, 이 문서는 **회차 사이의 관계와 관통 규칙**만 담는다.

## 1. 지금까지 만든 것

| 회차 | 무엇 | 축 |
|---|---|---|
| #333 | 9시 출근 · 정오 탕비실 · 21시 퇴근 · 승인 압력 4단계 · 밤 조명 | 시간 |
| #338 | 회의실 벽면 판(오늘의 할 일 3줄) · 연속 기록 · 퇴근 정산 종이 | 지시 |
| #234 · #274 | 책상 서류 더미(오늘 처리량) · 말풍선(지금 하는 일) | 상태 |

두 회차 모두 "지금 무슨 일이 일어나는가"와 "대표가 무엇을 해야 하는가"를 그렸다. **누적된 시간은 아직
화면에 없다** — 화면은 60일 근속과 첫날을 구분하지 않는다.

## 2. 실측 기준선 (2026-08-20)

```
창립 2026-06-22 · 60일차 · 누적 952건 · 성공 877 / 실패 75
실행 기록이 있는 워커 29종 / AGENT_REGISTRY 32종
```

KST 일별 최근 14일: 23 21 12 10 25 25 65 72 33 17 40 30 68 60 24

트리거 종류가 워커의 성격을 가른다 — 이 축이 세 회차 모두의 판정 근거다.

| 범주 | trigger_type | 뜻 |
|---|---|---|
| 자율 | `*_CRON` · `SCHEDULED` · `PR_REVIEW_SWEEP` · `SUBCONSCIOUS_TICK` | 스스로 돈다. 안 돌면 고장 |
| 호출 대기 | `SLACK_COMMAND_*` · `SLACK_MENTION_*` · `MANUAL` | 대표가 부를 때 돈다. 안 돈 것은 정상 |
| 이벤트 대기 | `WEBHOOK_*` | 외부 사건이 오면 돈다. 안 돈 것은 정상 |

## 3. 회차 계획

### 1회차 — 이력과 성적 (착수)

화면이 아직 말하지 않는 것: 누가 얼마나 오래·많이 일했나, 자율 워커가 멈춰 있나, 회사가 자라고 있나.

- 커서 쪽지에 개인 이력 두 줄 (근속 · 누적 · 최근 실행)
- 자율 워커 정지 표식 — 상시 표시
- 벽 게시판을 사보로 승격 — 창립 일차 · 누적 · 최근 추이

상세: `docs/superpowers/specs/2026-08-20-office-ledger-identity-design.md`

**왜 먼저인가** — 집계 하나로 세 화면이 다 나오고(다른 축 대비 코드량이 가장 적다), 새 UI 컨테이너를
만들지 않아 이름표 겹침 회귀 위험이 없다. 그리고 이 회차만이 **현재 화면이 감추고 있는 사실**을
드러낸다(자율 워커 정지).

### 2회차 — 생동감

1회차를 끝내도 화면은 여전히 하루 대부분 정지해 있다. 32명 중 26명은 출근해도 오늘 할 일이 0건이고,
움직임은 하루 세 번의 사건(출근·점심·퇴근)뿐이다.

- 옆자리 리액션 — 완료·실패에 옆 사람이 반응
- 서류 주고받기 — 핸드오프 체인(`AgentRun.parentId`)이 이미 있으므로 실제 데이터로 그릴 수 있다
- 잡담 · 창밖 날씨

**데이터가 필요 없는 축**이라 언제든 착수 가능하지만, 소품과 애니메이션이 좌석 몫을 먹으므로 겹침
회귀 위험이 세 회차 중 가장 크다. 1회차가 자리 잡은 뒤에 한다.

### 3회차 — 조작

지금 화면은 읽기만 된다. "PR #1005 리뷰 회수"를 보고도 GitHub로 직접 가야 한다.

- 회의실 판 항목에서 바로 실행 — PR 회수 · 실패 재시도 · 승인
- 실행은 예외 없이 PreviewGate 경유

**되돌리기 어려운 외부 부작용**이 걸리므로 마지막이다. 승인 카드 만료 경로가 canceller를 부르지 않는
기존 문제와 얽히므로, 착수 전에 그 경로부터 확인한다.

### 웹 렌더러 따라잡기 (3회차 직후)

맥(SpriteKit)과 웹(Electron) 두 화면을 매 회차 동시에 고치지 않는다 — 검증이 두 배가 되고, 맥에서
확정한 뒤 웹을 맞추는 선례가 이미 두 회차 있다. 3회차가 끝나면 세 회차분을 한 번에 옮긴다.

## 4. 회차마다 지키는 것

- **판정은 `ConsoleCore` 순수 함수, 실행은 `OfficeScene`.** 이미 `OfficeIdle`·`OfficeChoreography`·
  `OfficeAttendance`가 지키는 경계다
- **시각은 예외 없이 `OfficeScene.currentHour()` 경유.** `Date()` 직접 호출은 `--hour` 렌더 검증을
  무력화한다
- **백엔드는 집계만, 시각 판정은 하지 않는다.** 서버가 "지금 보여라"를 계산하면 서버 시각과 앱 시각이
  어긋날 때 화면이 조용히 빈다
- **게이트**: `swift build && swift run ConsoleCoreTests` (XCTest 없음 — `swift test`는 실패한다) +
  `pnpm lint:check && pnpm test && pnpm build`
- **렌더 검증은 두 창 비율 모두** — 실사용 창(960×1050)과 최소 창(960×563). 최소 창은 글자 하한 때문에
  배치가 다르다
- **에셋을 새로 뽑기 전에 코드로 그릴 수 있는지 본다.** 색·글자·빛은 코드가 싸다(`OfficeLightTexture`
  선례). 새 시트를 넣으면 코드 3곳을 고쳐야 하고 2곳만 고치면 조용히 실패한다

## 5. 세 회차 모두 안 하는 것

| 항목 | 왜 |
|---|---|
| 레벨 · 배지 · 포인트 | 이 회사는 이미 진짜 숫자를 갖고 있다(252건, 무결점 80연속, 56일 무실행). 가짜 척도를 씌우면 의미가 흐려진다 |
| 화면 밖 알림 (맥 통지 · Slack 재촉) | 승인 만료가 13일 연속 0건 — 존재하지 않는 문제에 알림을 다는 일 |
| 인구 변동 | 32명 고정. 실행이 많은 시각에 사람을 더 그리지 않는다 |
| 소리 | 없어도 아쉽지 않다 |
| 성적 추이 그래프 | 9주치 9점을 벽 한 칸에 그리면 점이 아니라 얼룩이 된다. 숫자 두 개의 비교가 더 정확하게 읽힌다 |
