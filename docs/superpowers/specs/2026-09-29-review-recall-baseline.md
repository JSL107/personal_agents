## 이 숫자가 말하는 것과 말하지 않는 것

- **재현율의 하한이다.** gemini 도 놓친 결함은 여기 안 잡힌다. 실제 이대리 재현율은 이 숫자와 같거나 낮다.
- **이대리가 gemini 보다 못하다는 뜻이 아니다.** 이대리만 잡은 결함은 이 대조의 분모에 없다. 이 조사는
  "gemini 가 찾은 정탐 중 이대리도 찾은 비율" 하나만 잰다.
- **재현할 수 없는 측정이다.** gemini Code Assist 소비자판이 종료돼("The consumer version of Gemini Code
  Assist on GitHub has been sunset", `sbe-api-v5-puppeteer#103` 요약 코멘트) 최근 PR 에는 인라인 지적이
  없다. 이 표본은 더 늘지 않는다.

- **실결함** — 현재 코드로 도달 가능한 잘못된 동작
- **경미** — 실결함이지만 영향이 CI 시간·로그 위생·드문 입력 정도

**타이밍 보정.** gemini 가 지적한 커밋과 이대리가 리뷰한 커밋이 다를 수 있다. 이대리가 리뷰한 head 에

## 해석

**1. 도메인 지식 부족으로 놓친 것은 없다.** D 는 0건이다. 도메인 냄새가 나는 건도 모두 다른 경로로
설명된다. 학년도 계산(#1)은 이대리가 짝 PR 에서 정확히 잡았고, 해체된 학교(#25)와 soft-delete 된 글(#17)은
같은 레포 안에 따라야 할 선례가 있었다. 외부 지식이 필요했던 2건(C)도 비즈니스가 아니라 NEIS API 코드
체계와 Node 스트림 의미다. 참고로 같은 C 유형인 "Express 라우팅은 대소문자를 가리지 않는다" 는 이대리가
`spinoff#2831` 에서 스스로 잡았다(카드 946·955).

**2. 가장 큰 덩어리는 "보였는데 결함으로 확정하지 않은 것" 이다.** A·A\* 16건 중 여럿에서 이대리는 바로
그 자리에 카드를 냈지만 결함이 아니라 **테스트 공백·미검증** 으로 냈다.

| PR | 이대리 카드 | gemini 가 짚은 결함 |
|---|---|---|
| `v5#1062` | 664 "실패 경로가 검증되지 않았다" | apply 실패가 무시되는 구조 |
| `v5#1058` | 647 "캐시 재사용 시나리오 미확인" | compose 쪽 캐시 키가 어긋남 |
| `v4#270` | 330 "빈 값 fallback 이 spec 으로 검증되지 않음" | 공백 값이 빈 URL 이 됨 |
| `v5#1082` | 775 "창별 scanned 결과 미확인" | 1일 창의 드리프트 누락 |

같은 지점을 보고도 "확인 못 한 것은 지적하지 않는다" 규칙 아래에서 테스트 공백 카드로 후퇴한 것으로 읽힌다.
원장 「이 국면」 ③ 이 "안 틀리는 대신 안 하고 있을 수 있다" 고 적어 둔 우려가 여기서 확인된다.

**3. 회차 변동이 크다.** dev·master 짝 PR 은 같은 diff 인데, 3쌍(#1·#2·#3)에서 한쪽만 결함을 잡았다.
놓친 16건의 A 계열 중 적어도 3건은 지식 문제가 아니라 같은 입력에 대한 출력 편차다. 한 번 돌린 결과로
재현율을 판단하면 안 된다는 뜻이기도 하다.

**4. B 9건은 diff 밖 탐색의 문제다.** 샤드 라우팅, 기본 LIMIT, 트랜잭션 커밋 의미, nullable 컬럼처럼
모두 레포 안에 답이 있다. 도메인 지식을 넣는 것이 아니라 diff 가 부르는 함수·테이블 정의를 따라가 읽게
하는 쪽이 대응이다.

## 목표 10 에 대한 결론

**비즈니스 상식 블록(목표 10)은 이 표본에서 근거를 찾지 못했다.** 놓친 27건 중 도메인 지식으로만 풀리는
것이 0건이다. 이 데이터가 가리키는 개입은 다음 둘이다.

- diff 안에서 보인 결함을 테스트 공백으로 돌리지 않게 하는 것(A 계열 16건). 판정 기준 쪽의 문제다.
- diff 가 호출하는 레포 내부 코드를 따라가 읽게 하는 것(B 9건). 탐색 범위 쪽의 문제다.

어느 쪽을 하든 성공 판정은 이 문서의 27건을 재리뷰해 몇 건을 새로 잡는지로 할 수 있다. 짝 PR 에서
보인 회차 변동 때문에 한 번이 아니라 여러 번 돌려 봐야 한다.
