# 오늘의 공부 — 그림 한 장 자동 첨부 설계

작성 2026-08-31 · 상태: 승인 대기 · 구현 전

## 1. 배경과 목표

오늘의 공부(`study-brief-cron`)는 매일 09:30에 주제를 하나 조사해 Slack 카드로 보내고, 같은 내용을 노션 데이터베이스에 페이지로 남긴다. 지금 그 페이지는 처음부터 끝까지 글자다. 콜아웃(왜 지금 나한테) · 본문 1,200~1,800자 · 출처 목록.

읽는 데 드는 비용이 그대로 남아 있다. 15분 분량으로 압축해 뒀지만, 압축된 글도 글이라 훑어서는 머리에 남지 않는다.

이 설계는 **그 페이지 맨 위에 주제를 한눈에 보여주는 그림 한 장을 붙인다.** 글을 읽기 전에 구조가 먼저 들어오게 하는 것이 목적이다.

그림의 성격은 `eli5` 스킬이 지향하는 것과 같다. 아무것도 모르는 사람 눈높이로, 문장이 아니라 도형과 화살표와 비유로 설명한다. 다만 그 스킬 자체는 Claude Code 안에서만 도는 것이라, **지침을 codex 프롬프트로 옮겨 심는다.**

### 성공 기준

- 노션 페이지를 열면 본문 위에 그림이 있고, **그 안의 글자가 그냥 읽힌다.**
- 그림 생성이 실패해도 페이지와 Slack 카드는 평소대로 나간다.
- 09:30을 기다리지 않고 그림만 따로 뽑아 눈으로 확인할 수 있다.

## 3. 핵심 문제 — 왜 글자가 깨지는가

이 설계에서 가장 중요한 부분이다.

노션 본문은 가로 폭이 고정된 액자다. 그보다 넓은 이미지를 넣으면 **노션이 액자에 맞춰 이미지 전체를 축소한다.** 그림 안의 글자도 같은 비율로 줄어든다.

```
1200px 캔버스  →  약 700px 액자  =  0.58배 축소
그림 안 16px 글자  →  화면에서 9px  →  읽을 수 없음
```

프롬프트에 "글자를 크게 그려라"라고 쓰는 것으로는 이걸 못 이긴다. 축소 배율은 캔버스 폭과 액자 폭의 비로 결정되는 물리량이지, 그림 내용의 문제가 아니기 때문이다.

### 해결 — 축소 배율을 1.0으로 만든다

**캔버스 가로를 액자 가로와 같게 잡는다.** 줄일 이유가 사라지므로 그린 글자 크기가 그대로 표시된다.

```
700px 캔버스  →  700px 액자  =  1.0배, 축소 없음
그림 안 16px 글자  →  화면에서 16px  →  읽힌다
```

### 선명도는 별개의 축이다

캔버스를 좁히면 화질이 나빠질 것 같지만 그렇지 않다. **표시 크기와 화소 밀도는 독립적이다.**

puppeteer의 `deviceScaleFactor: 2`는 논리 폭 700px 화면을 물리 픽셀 1400px로 촬영한다. 노션은 이 이미지를 700px 자리에 표시하므로 축소는 여전히 일어나지 않고, 고해상도 디스플레이나 확대 보기에서만 밀도가 살아난다.

| | 논리 폭 (글자 크기 기준) | 물리 픽셀 (선명도) |
|---|---|---|
| 값 | 액자 폭과 동일 | 논리 폭 × `deviceScaleFactor` |
| 무엇을 막나 | 글자 뭉개짐 | 흐릿함 |

### 세로는 제약이 아니다

액자가 강제하는 것은 가로뿐이다. 세로로 긴 이미지는 노션이 줄이지 않고 그대로 아래로 늘여 표시한다. 따라서 캔버스가 좁아도 답답한 그림이 되지 않는다 — 세로로 흐르는 카드 형태가 된다.

세로 상한을 두기는 하지만 이것은 깨짐 방어가 아니라 "한 번에 눈에 들어오는가"를 위한 제한이다.

### 액자 폭의 실제 값은 미확정

노션 본문 폭의 정확한 픽셀 값은 공식 문서에 명시되어 있지 않고 공개 자료도 엇갈린다. **추정치를 코드에 상수로 박지 않는다.** 환경변수로 빼고, 첫 그림을 실제 노션 페이지에 올려 눈금을 맞춘 뒤 기본값을 확정한다.

## 4. 전체 흐름

기존 파이프라인(`study-brief-cron.consumer.ts`)에서 ④만 새로 들어가고 ⑤가 확장된다.

```
09:30  ① 조사 (codex)             → 본문 마크다운          [기존]
       ② 왜 지금 나한테 (codex)   → 콜아웃 판정            [기존]
       ③ DB 저장                                           [기존]
       ④ 그림 (codex → 캡처)      → PNG                    [신규]
       ⑤ 노션 페이지 발행          = 콜아웃 + 그림 + 본문 + 출처  [확장]
       ⑥ Slack 카드 발송                                    [기존]
```

④의 내부는 다음과 같다.

```
  본문 + 판정
       ↓
  codex 에게 HTML 요청
       ↓
  HTML 추출 (파서)
       ↓
  puppeteer 로 띄움
       ↓
  ┌─ 렌더 검사 ─────────────────┐
  │ · 글자 크기 하한 미달 있나?  │
  │ · 가로로 삐져나갔나?         │
  │ · 세로 상한 넘었나?          │
  └──────────────────────────────┘
       ↓ 통과            ↓ 실패 (1회차)
   PNG 캡처         사유를 붙여 재요청 → 다시 검사
                          ↓ 실패 (2회차)
                     그림 없이 진행
```

## 5. 구성요소

새로 만드는 것은 네 덩어리다. 모두 이 레포에 이미 있는 패턴을 따른다.

### 5-1. 프롬프트 — `study-brief-cron/domain/study-diagram.prompt.ts`

`study-deepdive.prompt.ts`와 같은 형태의 순수 함수. 입력은 주제 · 종류 · 판정 · 본문이고 출력은 문자열 하나다.

담을 계약:

- 인라인 SVG와 인라인 CSS만. 외부 요청(CDN · 폰트 · 이미지 · fetch) 금지 — puppeteer가 네트워크를 기다리다 멈추는 것을 막는다.
- 캔버스 가로는 정확히 `STUDY_DIAGRAM_WIDTH_PX` px. 이 폭을 넘는 요소를 두지 않는다.
- 글자는 최소 `STUDY_DIAGRAM_MIN_FONT_PX` px 이상. 문장이 아니라 낱말과 짧은 구로.
- SVG의 `width`/`height`를 `viewBox`와 같은 값으로 둔다 — 스케일 변환이 끼면 검사와 실제 표시가 어긋난다.
- 설명의 뼈대는 도형 · 화살표 · 크기 대비가 지고, 글은 이름표 역할만 한다.
- 회사명 · 학교명 · 사내 시스템 이름을 쓰지 않는다 (기존 익명화 정책과 동일).

두 수치는 프롬프트를 만들 때 실제 숫자로 치환해 넣는다 — 모델에게 변수 이름을 그대로 보여주지 않는다.

출력 형식은 ```` ```html ```` 코드펜스 하나로 고정한다.

**재작업 프롬프트는 지시를 덧붙이지 않고 치환한다.** 실패 사유를 앞에 붙이는 방식은 원래 지시와 충돌하면 무시되는 사례가 이 레포에 축적되어 있다. 위반한 항목의 지시문 자체를 구체적 수치와 함께 다시 쓴다.

### 5-2. 파서 — `study-brief-cron/domain/study-diagram.parser.ts`

codex 출력에서 HTML만 꺼낸다. `study-research.parser.ts`와 같은 모양(성공/실패 유니온 반환, 예외 대신 사유 문자열).

- 코드펜스 안쪽을 취한다. 펜스가 없으면 실패로 본다 — 설명 산문이 섞인 것을 HTML로 오인하지 않기 위해서다.
- 문자열 안에 코드펜스가 들어 있는 경우가 있으므로, 후보를 고를 때 "그럴듯한 위치"가 아니라 **`<html`/`<svg` 포함 여부로 검증**해 고른다.
- 외부 리소스 참조(`http://`, `https://`, `//`로 시작하는 `src`/`href`)가 있으면 실패로 본다. 프롬프트 계약 위반이자 캡처 지연 원인이다.

### 5-3. 렌더러 — `study-brief-cron/infrastructure/study-diagram.renderer.ts`

puppeteer로 HTML을 띄우고, 재고, 찍는다. **puppeteer는 이미 설치되어 있다** (`crawler.requester.ts`가 사용 중). 새 의존성은 없다.

`crawler.requester.ts`의 자원 정리 패턴(브라우저·페이지 확실히 닫기, 정리 실패와 본 작업 실패를 구분)을 그대로 따른다.

```
viewport      width = 액자 폭, deviceScaleFactor = 2
setContent    로컬 문자열, waitUntil 은 네트워크 대기 없이
검사          page.evaluate 로 DOM 측정
캡처          fullPage PNG
```

#### 검사 세 가지

브라우저 안에서 재므로 추가 비용이 없다. 측정은 **`getBoundingClientRect()` 기준**으로 한다 — computed font-size만 보면 SVG `viewBox` 스케일이 반영되지 않아 실제 표시 크기와 어긋난다.

| 검사 | 판정 | 잡는 것 |
|---|---|---|
| 글자 크기 | 텍스트를 가진 리프 요소 중 실제 렌더 높이가 하한 미달인 것이 1개라도 있으면 실패 | 작은 글씨 |
| 가로 넘침 | 어떤 요소의 오른쪽 끝이 캔버스 폭을 넘으면 실패 | 잘려나간 그림 · 박스를 밀어낸 긴 문장 |
| 세로 상한 | 문서 전체 높이가 상한을 넘으면 실패 | 한눈에 안 들어오는 그림 |

실패 시 **어떤 요소가 어떤 값으로 걸렸는지**를 함께 반환한다. 재작업 프롬프트의 재료이자, 사람이 로그를 볼 때의 근거다.

이 게이트를 만든 뒤에는 **일부러 위반하는 HTML을 넣어 실제로 걸리는지 확인한다.** 통과만 시켜보고 넘어가면 검사가 죽어 있어도 알 수 없다.

### 5-4. 노션 파일 업로드 — `notion/infrastructure/`

현재 SDK는 `@notionhq/client@2.3.0`이고 파일 업로드 헬퍼가 없다(`client.fileUploads`가 `undefined`). 최신은 5.26.0으로 메이저 세 칸 차이라, 업그레이드하면 이 레포의 모든 노션 경로가 영향권에 들어간다.

**SDK는 건드리지 않고, 이 세 엔드포인트만 `fetch`로 직접 호출한다.**

```
1. POST /v1/file_uploads
   { filename, content_type: "image/png" }  →  { id, upload_url }

2. POST /v1/file_uploads/{id}/send
   multipart/form-data, 필드명 "file"

3. 블록에 첨부
   { type: "image", image: { type: "file_upload", file_upload: { id } } }
```

- 인증은 기존과 같은 `NOTION_TOKEN` (`notion.module.ts:22-27`).
- `Notion-Version` 헤더가 필요하다. SDK 2.3.0이 보내는 값은 파일 업로드를 지원하지 않을 수 있으므로 **이 호출에만 별도 버전을 명시**한다. 정확한 최소 지원 버전은 구현 시 실호출로 확정한다.
- 제한: 파일 20MB, **업로드 후 1시간 안에 붙이지 않으면 자동 폐기**. 캡처 직후 곧바로 붙이므로 여유가 있다. 700×1600 @2x PNG는 수백 KB 수준이라 용량도 무관하다.

`NotionPlanBlock`에 `image` 타입이 추가된다 (`notion-client.port.ts`). 이 타입은 텍스트 블록이 아니므로 기존 `NotionTextBlock` 교차 타입에 넣지 않는다.

### 5-5. 퍼블리셔 확장 — `study-brief-notion.publisher.ts`

`buildPageBlocks`가 그림 블록을 하나 더 끼운다. 위치는 **콜아웃 다음, 본문 앞**이다.

```
콜아웃 (왜 지금 나한테)
그림               ← 신규
구분선
본문
구분선
출처
```

`PublishStudyBriefInput`에 업로드 완료된 파일 id가 선택 필드로 들어간다. 값이 없으면 그림 블록을 넣지 않는다 — 그림 유무가 발행 성패를 가르지 않는다.

## 6. 실패 처리

그림은 **있으면 좋은 것**이지 페이지를 막을 이유가 아니다. 아래 어느 단계에서 실패해도 노션 페이지와 Slack 카드는 평소대로 나간다.

| 실패 지점 | 처리 |
|---|---|
| codex 호출 실패 · 빈 응답 | 그림 생략. 재시도 없음 |
| HTML 파싱 실패 | 그림 생략 |
| 렌더 검사 1회차 실패 | 사유를 넣어 재작업 1회 |
| 렌더 검사 2회차 실패 | 그림 생략 |
| 캡처 실패 · 타임아웃 | 그림 생략 |
| 노션 업로드 실패 | 그림 없이 페이지 발행 |

**codex 호출 실패에 재시도를 두지 않는 이유**: 쿼터 소진 한 건이 뒤따르는 일정까지 연쇄로 무너뜨린 사례가 이 레포에 있다. 재작업 1회는 "쓸 수 없는 그림이 나왔을 때"에만 쓰고, 호출 자체가 실패한 경우에는 즉시 포기한다.

생략할 때마다 **왜 생략했는지를 로그에 남긴다.** 조용히 0건이 되는 실패는 에러보다 오래 산다.

## 7. 검증

### 7-1. 수동 진입점 — `scripts/study-diagram.ts`

cron에만 걸린 기능은 실증 입구가 없어 검증이 09:30 대기에 묶인다. 저장된 최근 공부 한 건을 골라 **그림만 뽑는 CLI**를 함께 만든다.

```
pnpm exec ts-node scripts/study-diagram.ts            # 가장 최근 공부
pnpm exec ts-node scripts/study-diagram.ts --id <id>  # 특정 건
pnpm exec ts-node scripts/study-diagram.ts --dry      # 노션 업로드 없이 PNG 만
```

HTML과 PNG를 로컬에 남겨 눈으로 본다. 마음에 안 들면 프롬프트만 고쳐 다시 돌린다.

### 7-2. 액자 폭 눈금 맞추기

1. 임의 폭으로 그림 한 장을 만들어 실제 노션 페이지에 올린다.
2. 노션에서 축소가 일어나는지 확인한다.
3. 축소가 없는 최대 폭을 찾아 기본값으로 확정하고, 문서에 그 근거를 남긴다.

이 절차를 마치기 전에는 cron을 켜지 않는다.

### 7-3. 게이트 역방향 확인

검사 세 가지 각각에 대해, **일부러 위반하는 HTML로 실제로 실패하는지** 확인한다. 통과 케이스만 보면 게이트가 무력화되어 있어도 초록으로 보인다.

### 7-4. 레포 게이트

`pnpm lint:check && pnpm test && pnpm build` 3중 통과. 환경변수를 추가하므로 `pnpm docs:check`도 함께 돌린다.

## 8. 환경변수

기본값은 **꺼짐**이다. 검증을 마친 뒤 켠다.

| 이름 | 필수 | 설명 |
|---|---|---|
| `STUDY_DIAGRAM_ENABLED` | ❌ | 그림 첨부 사용 여부. 기본 false |
| `STUDY_DIAGRAM_WIDTH_PX` | ❌ | 캔버스 가로 = 노션 본문 폭. 7-2에서 확정 |
| `STUDY_DIAGRAM_MIN_FONT_PX` | ❌ | 글자 크기 하한 |
| `STUDY_DIAGRAM_MAX_HEIGHT_PX` | ❌ | 세로 상한 |

추가 시 네 곳을 함께 갱신한다: `.env.example` · `.env` · `src/config/app.config.ts` · README 표. `docs/env-catalog.md`도 같이 채운다.

## 9. 범위 밖 · 후속

- **딥다이브(11:00) 블로그 초안에는 붙이지 않는다.** 블로그는 발행 경로가 따로 있고 이미지 처리 방식도 다르다. 오늘의 공부 노션 페이지에서 먼저 굴려보고 판단한다.
- **Slack 카드에는 넣지 않는다.** 노션 링크를 타고 들어가면 보인다.
- **본문 안 mermaid 도표**는 이번 범위가 아니다. 프롬프트 한 줄로 가능하고 배선도 이미 있지만(`markdown-to-blocks.ts:23`), 그림과 성격이 달라 섞으면 판단이 흐려진다.
- **노션 SDK 5.x 업그레이드**는 하지 않는다. 이번에 필요한 것은 엔드포인트 세 개뿐이다.
- **과거 공부에 소급 적용**하지 않는다.
