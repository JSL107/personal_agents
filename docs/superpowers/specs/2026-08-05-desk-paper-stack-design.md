# 책상 위 서류 더미 — 오늘 처리한 일을 화면으로 보여주기

작성일: 2026-08-05 · 대상: `clients/idaeri-console` (오피스 씬) + `src/console` (스냅샷)

## 왜 만드나

같은 날 세션 자동 분배 기능을 폐지했다(#233). 유휴 CLI 세션을 찾아 "이 작업을 맡길까요?"
승인 카드를 만들고, 승인하면 그 세션에 지시를 밀어 넣던 기능이다. 두 가지가 문제였다.

- 다른 세션이 진행 중이던 대화 맥락에 외부에서 작업을 끼워 넣어 오염 위험이 컸다.
- 카드가 슬랙으로 가지 않고 콘솔 승인 목록에만 쌓여, 닷새간 하루 18장을 만들면서 승인은 0건이었다.

그 기능이 하려던 것 자체 — "지금 노는 사람이 있다 / 저쪽에 일이 몰려 있다"를 알리는 것 — 은
여전히 필요하다. 방식만 바꾼다. **작업을 밀어 넣는 대신 상태를 드러낸다.**

## 무엇을 셀 것인가 — 조사 결과

"대기 큐"를 세려 했으나, 이 시스템에는 그렇게 부를 만한 것이 사실상 없다. 실측(2026-08-05):

| 후보 | 실제 값 | 판정 |
|---|---|---|
| 승인 대기 카드 (`preview_action` PENDING) | 1건 (누적 137건 중). 그 1건도 폐지된 `SESSION_INJECT` | 거의 항상 0. 이미 대표실 앞 줄서기로 표현 중 |
| 실행 대기 (`agent_run`) | 상태값이 `IN_PROGRESS`/`SUCCEEDED`/`FAILED` 셋뿐 | "대기 중"이라는 상태 자체가 없음 |
| BullMQ 큐 깊이 (10종) | cron·webhook이 발화 즉시 소비 | 쌓이지 않음 |
| 슬랙 인박스 미처리 | 테이블 전체 0행 | 죽은 데이터 |
| 변화감지 제안 PENDING | 7건, 전부 `CODE_REVIEWER` | 기본 OFF 기능의 정체분 |
| 최근 실행량 (`agent_run`) | `CODE_REVIEWER` 24시간 22건·7일 48건 / 나머지 전원 0~1건 | 값이 실제로 움직이고 편차가 큰 유일한 신호 |

이대리는 일이 큐에 쌓였다가 처리되는 구조가 아니라, 정해진 시각이나 이벤트에 발화해 즉시
실행되는 구조다. 그래서 밀린 양은 늘 0에 가깝고, 대신 **누가 얼마나 많이 돌았는지**는 20배 넘게 갈린다.

**결정: 오늘 자정 이후 성공적으로 끝낸 실행 건수를 센다.** 뜻은 "밀린 일"이 아니라 "해낸 일"이고,
아침에는 전원 책상이 비었다가 하루가 갈수록 쌓여 자정에 비워지는 그림이 된다.

## 건수 → 장수

| 오늘 끝낸 건수 | 서류 |
|---|---|
| 0 | 없음(빈 책상) |
| 1 | 1장 |
| 2~3 | 2장 |
| 4~7 | 3장 |
| 8~15 | 4장 |
| 16 이상 | 5장 |

두 배마다 한 장 오르는 눈금이다. 선형(1건=1장)을 쓰면 코드리뷰어가 하루 대부분 최대치에
붙어 "조금 바쁨"과 "매우 바쁨"이 같은 그림이 된다.

## 구조

### 서버 — 숫자 하나를 스냅샷에 얹는다

`ConsoleAgent`에 `doneToday: number`를 추가하고, `ConsoleReadService.getSnapshot`이 조립할 때
채운다. 집계는 이미 비서실 브리핑이 쓰는 것과 조건이 같다(끝난 시각 기준 · 성공만) —
`aggregateSucceededCounts`의 안쪽을 "이 시각 이후"를 받는 형태로 쪼개고, 기존 호출부는
"며칠 전부터"를 유지한다. 비서실 동작은 바뀌지 않는다.

실시간 이벤트(SSE)는 만들지 않는다. 앱이 이미 30초마다 스냅샷을 다시 싣고
(`AppRootView.startSnapshotResync`), 서류 더미는 초 단위로 볼 정보가 아니다.

### 앱 — 책상 노드의 자식으로 붙인다

책상 스프라이트는 이미 사람별로 잡혀 있다(`deskNodes[agentType]`, 모니터 깜빡임이 쓰는 노드).
서류를 그 노드의 **자식**으로 붙이면 창 크기 변경으로 책상이 다시 그려질 때 위치와 앞뒤
순서가 저절로 따라온다.

건수를 장수로 바꾸는 계산은 `ConsoleCore`(화면과 분리된 순수 코드)에 둔다. 씬에 숫자를
박으면 테스트가 닿지 않는다.

앉은 사람은 책상 바로 위 칸에 있고 `officeSeatedSpriteDrop`만큼 내려와 책상에 걸치므로,
서류는 책상 오른쪽으로 치우쳐 놓는다. **정확한 위치는 오프스크린 렌더로 눈으로 보고 맞춘다** —
좌표만으로는 겹침 여부를 알 수 없다.

### 에셋

`desk-paper.png` 낱장 한 장을 도트로 그리고, 코드에서 조금씩 어긋나게 겹쳐 쌓는다. 장수별
그림을 따로 만들지 않는 이유는 한 장이면 장수를 코드로 조절할 수 있기 때문이다. 색은 기존
가구에서 뽑은 종이 흰색·그늘색을 그대로 쓴다.

## 검증

- 백엔드 `pnpm lint:check && pnpm test && pnpm build` 3중 통과
- 콘솔 `swift build` + `swift test`
- 눈금 회귀 테스트: 0·1·2·3·4·7·8·15·16·100건 → 0·1·2·2·3·3·4·4·5·5장
- 오프스크린 렌더로 시각 확인 — 서류가 사람·이름표·모니터를 가리지 않는지, 5장에서 책상 밖으로
  넘치지 않는지

## 범위 밖

- 승인 대기 카드를 서류로 표현하지 않는다. 이미 대표실 앞 줄서기가 같은 정보를 보여준다.
- 실패한 실행은 세지 않는다. 이미 빨간 링과 엎드린 자세로 표현된다.
- 클릭·툴팁 같은 상호작용은 넣지 않는다.
- 별도로 진행 중인 책상 소품 작업(`prop-papers.png` 등)과 파일명을 겹치지 않게 두었다. 두 작업이
  모두 들어오면 서류 그림이 두 종류가 되는데, 통합은 그쪽이 머지된 뒤의 후속 항목이다.
