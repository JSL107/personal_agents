## 1. 왜 다시 설계하나

PO Shadow 단계 3(#773, 2026-10-08)이 `ProductGoal` 을 들여왔지만 **13일 동안 한 번도 쓰이지 않았다.**

| 측정 (2026-10-21, 로컬 DB) | 값 |
|---|---|
| `product_goal` 행 | 0 |
| `preview_action` 중 `PRODUCT_GOAL` 카드 | 0 (생성 이력 자체가 없음) |
| 10-08 이후 라우터를 거친 대화 | 75건 |
| 그중 "목표"가 들어간 대화 | 0건 |
| 같은 기간 PO Shadow 실행 | 매일 (30일 30회) |

등록을 시도했다가 실패한 것이 아니라 **시도한 적이 없다.** 코드에서 확인한 원인은 셋이다.

1. **존재를 알 길이 없다.** 활성 목표가 0개면 PO 보고는 단계 3 이전과 똑같이 나가도록 의도돼 있다
   (`generate-po-shadow.usecase.ts:152-155`). 사용법은 분류기 프롬프트(`worker-capability.ts:56-58`)와 PR 본문에만 있다.
2. **등록 문장이 까다롭다.** `DECLARE_PATTERN`(`product-goal.ts:53`)에 맞는 "분기/제품 목표는 …" 형식에 "달성 기준은"과
   숫자·완료어(`COMPLETION_MARKER`)가 있어야 하고, 하나라도 빠지면 카드 없이 거절된다. 수정 경로는 없다(닫고 재선언).
3. **등록해도 연결이 약하다.** 목표와 작업은 PR·이슈 **제목의 키워드 부분 문자열**로만 잇는다(`isLinkedToGoal`).
   한국어 키워드는 영어 PR 제목에 잡히지 않고, 짧은 키워드는 과하게 잡힌다.

사용자 인터뷰(2026-10-21)에서 확인한 조건:

- 목표의 크기를 하나로 정할 수 없다 — 분기 방향과 이번 달 할 일이 섞인다.
- 목표는 주로 **머릿속**에 있다. 적어 둔 곳이 없다.
- 이대리가 **먼저 말을 거는 것은 언제나 환영**한다.
- 목표가 있으면 듣고 싶은 것: **얼마나 진행됐나 · 달성에 무엇이 부족한가 · 잊은 목표 리마인드 · 목표 기반 아이디어.**
- 주간 점검은 **한 주의 시작(월요일 아침)**. 매일 PO 보고의 목표 기반 아이디어도 원했으나 후속으로 미룬다(§3).

코드 없이 같은 질문을 두 번 던진 수동 테스트(2026-10-21·10-27)에서 두 번 모두 답이 왔다. 다만 답의 모양이 설계의 전제와 달랐다.

| 회차 | 답 | 끝났다고 볼 기준 |
|---|---|---|
| 1 | 이대리 오피스 고도화하기 | "상세목표는 고민해봐야 할 듯" |
| 2 | 나만의 개인비서 만들기 (오피스 고도화는 그 아래) | "무엇이든 말로 시키면 처리해 준다" — 정량화는 어렵다 |

두 번 모두 **방향은 바로 나왔지만 끝이 있는 숙제는 나오지 않았다.** 방향 목표를 숙제처럼 다루면 모든 작업이 그 목표에 붙고
점검은 매주 "진척 판정 불가"만 낸다. 그래서 목표를 두 종류로 나누고(§4-2), 방향만 있을 때 숙제를 끌어내는 질문을 둔다(§4-3).

## 2. 목표와 성공 기준

**목표**: 이대리가 먼저 물어 머릿속 목표를 받아 두고, 매주 월요일에 그 목표 기준으로 진척·잊은 목표를 알려 준다.
첫 PR 은 "묻고 → 답을 받아 → 목표로 등록" 하나만 확실히 되게 한다. 지난 실패가 "기능이 있는지 몰라서 안 썼다"였기 때문이다.

**성공 기준 (2단계 배포 후 4주 안에 판정)**

- 숙제(`TASK`) 목표가 1개 이상 등록된다. 방향 목표만으로는 통과하지 않는다 — 수동 테스트에서 이미 방향은 나왔다.
- 월요일 점검 4회 중 사용자 반응이 2회 이상 있다. 반응은 `slack_delivery` 의 해당 발송 행
  `reaction_count + reply_count > 0` 과 점검 카드의 `preview_action` 상태 전이(승인·취소)로 센다.

**중단 신호** — 월요일 점검 4회 연속 무반응이거나, 4주 안에 활성 목표가 0개로 돌아가면 기능 전체를 다시 판정한다
(유지·축소·삭제). 같은 기능이 두 번 "0회 사용"으로 남지 않게 하려는 장치다.

## 3. 범위 밖

- **매일 PO 보고의 목표 기반 아이디어** — 후속. 판정(§6 3단계)에서 "유지"가 나오면 따로 설계한다. 지금 붙이지 않는 이유:
  PO 보고는 어긋남이 없는 회차를 `quiet` 로 끝내 채널에 내지 않으므로(`po-shadow.autopilot-task.ts:68-73`,
  모델 호출 조건 `generate-po-shadow.usecase.ts:170-175`) 섹션만 붙이면 거의 발송되지 않는다. 고치려면 보고 스키마·윤문 어댑터·
  아이디어별 반응 수집(현재 `SlackReactionSignal` 은 메시지 단위)·이심사 단건 호출까지 바뀌어 1·2단계보다 크다.
- 목표 계층(상위·하위 목표), OKR 구조 — 평면 목록으로 받는다. 방향과 숙제의 연결(`parentId`)도 보류한다.
  방향이 하나뿐인 지금은 모든 숙제가 그 아래라 연결이 새 정보를 주지 않는다. 방향이 2개 이상 등록되면 다시 본다.
- AI 기반 목표–작업 연결 판정 — 보류. 연결은 기존 키워드 부분 문자열(`isLinkedToGoal`)을 그대로 쓰되,
  키워드를 사용자가 쓰는 대신 초안 카드에서 AI가 한국어·영어 식별자를 섞어 제안한다(§4-2). 키워드로 놓치는 사례가 점검에서 보이면 그때 도입한다.
- 노션 등 외부 도구에서 목표 가져오기, 레포·라벨 기반 연결.

## 4. 사용자 흐름

### 4-1. 묻기 — 이대리가 먼저 말을 건다

- 매주 월요일 09:15 KST, 활성 목표가 0개면 **DM** 으로 묻는다. 09:00 은 `run-retro`·`idea-triage` 와 겹쳐 피한다
  (`autopilot.playbook-defaults.ts:30,51`).
  > 🧭 요즘 머릿속에 있는 목표가 있어요? 크기 상관없이 대충 말해 주세요. 제가 정리해서 보여 드릴게요.
- 목표가 있으면 2단계의 월요일 점검(§4-3)이 대신 나간다. 질문과 점검은 같은 날 둘 다 나가지 않는다.
- DM 으로 보내는 이유: 채널의 멘션 없는 스레드 답장은 수신되지 않는다. 이벤트 구독은 `app_mention` 과
  `channel_type === 'im'` 인 `message` 뿐이다(`router-message.handler.ts:176-215,221-223`).

### 4-2. 답 받기 — 분류기를 거치지 않고 초안 카드로

**답 수신** — 질문을 보낼 때 "목표 질문 대기" 표지(사용자, 질문 시각, TTL 72시간)를 남긴다. 라우터는 분류기보다 먼저 이 표지를 보고
그 사용자의 다음 DM 을 목표 초안 생성으로 넘긴다. `tryHandleGapTopicSelection`(`router-message.handler.ts:442`)과 같은
인터셉터 패턴이다. 분류기 문구만 늘리는 안은 쓰지 않는다 — "주제가 안 잡힌 추상적 요청은 UNKNOWN"
(`intent-classifier-system.prompt.ts:47`) 규칙 때문에 "나만의 개인비서 만들기" 같은 답이 버려진다.
"없어"·"나중에" 같은 답은 표지만 지우고 짧게 받는다.

**초안 카드** — AI가 답을 목표 초안으로 정리해 `PRODUCT_GOAL` 확인 카드로 보낸다. **한 번에 카드는 1장**이다.
한 답에 목표가 여럿이면 첫 번째를 카드로 만들고 나머지는 승인 뒤 이어서 묻는다. 자연어 "응/아니"는 사용자별
최근 PENDING 카드 1건에만 적용되기 때문이다(`findLatestPendingForUser`).

**목표의 두 종류**

| 종류 | 예 | 끝 기준 | 점검에서 하는 일 |
|---|---|---|---|
| 🧭 방향 (`DIRECTION`) | 나만의 개인비서 만들기 | 정성 문장이어도 되고 비워도 된다 | 진척을 계산하지 않음. 숙제가 없으면 끌어내기 질문 (§4-3) |
| ✅ 숙제 (`TASK`) | 오피스 화면에 오늘 일정 띄우기 | 필수, 흐리면 한 번 되묻는다 | 지난주 관련 작업·기한·잊은 목표 (§4-3) |

| 칸 | 필수 | 설명 |
|---|---|---|
| 제목 | ✅ | 한 줄 |
| 종류 | ✅ | AI가 제안해 카드에 표시. 사용자가 승인하거나 답장으로 바꾼다 |
| 왜 | — | 이 목표가 중요한 이유 |
| 끝났다고 볼 기준 | 숙제만 ✅ | 숙제가 흐릿하면 "끝난 건 어떻게 알 수 있을까요?"를 한 번 되묻는다. 방향은 묻지 않는다 |
| 키워드 | — | 숙제의 작업 연결용. AI가 한국어·영어 식별자를 섞어 제안한다 |
| 기한 | — | 없어도 된다 |

- 되묻기에 "숫자로 만들기 어렵다"고 답하면 AI는 종류를 **방향으로 바꿔 제안**하고 카드에 그렇게 표시한다. 자동으로 바꾸지 않는다 —
  숙제가 방향으로 빠져나가는 구멍이 되지 않게 사용자가 승인한다.
- **수정**: 카드가 PENDING 인 동안 같은 사용자가 DM 으로 고칠 내용을 보내면 이전 카드를 취소하고 고친 새 카드를 보낸다.
  기존 카드의 payload 를 고치는 경로(`UpdatePreviewPayloadUsecase`)는 쓰지 않는다 — 텍스트로 어느 칸을 고칠지 해석하는 코드가 따로 필요해진다.
- 기존 "분기 목표는 …" 문장 선언과 "목표 보여줘"·"목표 닫아줘"는 그대로 둔다(빠른 경로). 선언으로 만든 목표는 `TASK` 다.
- **상한**: `MAX_ACTIVE_PRODUCT_GOALS = 3`(`product-goal.ts:6`)은 `TASK` 만 센다. `DIRECTION` 은 별도로 최대 2개.
  카드를 만들 때 남은 자리가 없으면 카드 대신 "숙제가 3개 차 있어요. 하나를 닫을까요?"로 답한다(승인 뒤 거절되지 않게).

>
> 🧭 **나만의 개인비서 만들기** (방향)

- **숙제 목표**: 지난 7일 머지 PR·열린 이슈 중 키워드로 연결된 것(`isLinkedToGoal`)과 기한 상태를 보여 준다.

  답은 §4-2 의 같은 대기 표지·초안 카드 흐름을 탄다. 2주 연속 답이 없으면 4주 동안 질문을 쉰다(`slack_delivery.reply_count` 로 센다).
- **실행 단위**: `PO_SHADOW` 실행 모드로 두지 않고 별도 autopilot 태스크 `goal-checkin` 으로 만든다. PO 실행 원장에 섞이면
  다음 PO 회차가 점검 실행을 "직전 회차"로 읽고(`loadPreviousReportedFacts`, `generate-po-shadow.usecase.ts:369-375`)
  주간 요약의 PO 집계(`weekly-summary.autopilot-task.ts:251-259`)에 들어간다. PM 계획이 없는 날 `NO_RECENT_PLAN`
  (`generate-po-shadow.usecase.ts:106-117`)으로 점검까지 멈추는 문제도 피한다. 모델 호출이 없으므로 새 `AgentType` 도 필요 없다.
  1단계의 질문 발송도 같은 태스크의 "목표 0개" 분기다.

## 5. 구현 설계

### 5-1. 데이터 변경 (`ProductGoal`)

| 변경 | 이유 |

### 5-3. 모델 출력 검증 (초안 생성)

초안 생성만 모델을 쓴다. 출력은 그대로 쓰지 않고 코드가 다시 건다.

- 형태는 `outputSchema` 로 받는다. 이 요청은 Claude 폴백을 타지 않으므로(CLAUDE.md §0) 실패하면 "지금 정리가 안 됐어요, 다시 말해 주시겠어요?"로 답하고 대기 표지를 유지한다.
- `kind` 가 두 값 중 하나인지, `TASK` 면 기준이 있는지를 `findGoalDeclarationProblem` 으로 다시 검사한다. 걸리면 되묻기 재료로 쓴다.
- 사용자 답은 외부 텍스트로 보고 `wrapUntrustedInput` 으로 감싼다.

## 7. 위험

- **답이 목표로 이어지지 않음** — 대기 표지 TTL(72시간)이 지난 뒤의 답은 일반 대화로 간다. 판정 때 질문 발송 수 대비 표지 소비 수를 같이 본다.
- **방향만 쌓임** — 끌어내기 질문에도 숙제가 안 나오면 점검이 방향 한 줄에 그친다. §2 첫 기준(숙제 1개 이상)과 중단 신호가 잡는다.
- **키워드 연결 오류** — 짧은 키워드는 과하게, 한국어 키워드는 영어 PR 제목에 안 잡힌다. 점검에 연결된 PR 번호를 그대로 보여 줘 눈으로 확인하게 하고, 놓침이 반복되면 AI 연결(§3)을 도입한다.
- **알림 피로** — 월요일 DM 1통만 늘어난다. 끌어내기 질문은 쉬기 규칙이 있다.

## 8. 아직 정하지 않은 것

- 잊은 목표 주수(2주)·끌어내기 쉬기(2주 무응답 → 4주)·대기 표지 TTL(72시간) 조정 — 3단계 판정 때 재검토.
- 분기 첫 월요일에 목표가 있어도 "새 목표가 있나요?"를 덧붙일지 — 2단계 이후.
