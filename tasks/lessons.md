# Lessons

## 2026-08-05 — 영속화 후 발송 실패의 멱등 경계

- 저장을 마친 뒤 발송하는 전체 파이프라인에서 발송 실패가 발생해도 완료 guard를 해제하지 않는다. 재시도가 파이프라인 처음부터 시작하면 조사·판정·저장이 중복된다.
- 멱등 회귀 spec은 배열형 반환 mock이 아니라 key 상태를 보존하는 fake로 `acquireOnce`/`isDone`/`release` 의미를 재현한다.
- 요약과 상세처럼 중요도가 다른 다단 발송은 오류 경계를 분리한다. 정본이 DB에 있으면 상세 발송 실패는 warn으로 남기고 이미 성공한 요약을 무효화하지 않는다.
