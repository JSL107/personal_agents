# 이대리 오피스 — 웹 렌더러 · 윈도우 앱

맥이 계산한 사무실 배치를 받아 **브라우저 Canvas 로 그리는** 화면. 화면 전송이 아니라
그림을 이쪽에서 직접 그리므로, 같은 코드를 Electron 으로 포장해 **윈도우 PC 에 설치**한다
(→ [윈도우 PC 에 설치하기](#윈도우-pc-에-설치하기)). 맥은 데이터만 주고 그림은 윈도우가 그린다.

## 브라우저로 띄우기

```bash
# 1. 평면도를 뽑는다 (백엔드가 켜져 있어야 한다 — 사람이 0명이면 좌석도 0개다)
cd ../idaeri-console
for cols in 3 2; do
  IDAERI_CONSOLE_URL=http://127.0.0.1:3099 \
    .build/arm64-apple-macosx/debug/IdaeriConsole \
    --layout-json ../office-web/layout-$cols.json --zone-columns $cols
done

# 2. 서버를 띄운다 (정적 파일 + /v1/* 를 백엔드로 넘기는 프록시)
cd ../office-web
IDAERI_CONSOLE_URL=http://127.0.0.1:3099 python3 serve.py 8777
```

http://127.0.0.1:8777 을 연다.

> **백엔드 주소는 맥 앱과 같은 규칙**(`IDAERI_CONSOLE_URL`, 기본 `127.0.0.1:3002`)을 쓴다.
> 실운영은 `3099` 라 위 예시가 그 값을 지정한다 — 맥 앱을 띄울 때도 같은 값을 준다.
> 포트가 어긋나면 `/v1/*` 가 502 로 떨어지고, 어느 주소를 두드렸는지 응답에 함께 나온다.

## 평면도를 다시 뽑아야 할 때

`layout-*.json` 은 **스냅샷 시점의 사진**이다. 사람이 늘거나 줄면, 부서 편성이 바뀌면,
배치 규칙이나 에셋이 바뀌면, 출퇴근 시각 경계가 바뀌면 다시 뽑아야 한다. 상태(무슨 일이 도는지)는 실시간으로 받으므로
다시 뽑을 필요가 없다.

## 윈도우 PC 에 설치하기

브라우저 대신 **설치 파일(.exe)** 로 만든다. `serve.py` 가 하던 프록시 역할은 Electron 메인
프로세스(`main.js`)가 맡는다 — 창을 loopback 서버에 붙이므로 `live.js` 의 `fetch`·`EventSource`
가 개발 때와 **같은 코드로** 돈다(브라우저 출처 제약을 끄지 않는다).

```bash
# 평면도를 먼저 뽑는다 — 위 「브라우저로 띄우기」 1번과 같은 명령이다
cd clients/office-web
pnpm install

pnpm start      # 맥에서 그대로 띄워 본다
pnpm dist:win   # dist/IdaeriOfficeSetup-<버전>.exe 를 만든다
```

만든 `.exe` 를 윈도우 PC 로 옮겨 실행한다(`dist/` 는 저장소에 올리지 않는다).

`pnpm dist:win` 은 평면도가 없으면 빌드 전에 끊는다 — 없는 채로 만들면 **텅 빈 사무실이
설치되고**, 그게 "백엔드가 꺼져 있다" 와 구별되지 않는다.

### 첫 실행

설정 화면이 먼저 열린다. 맥의 주소를 넣는다.

| 어디서 보나 | 주소 |
|---|---|
| 같은 공유기 | 맥의 내부 주소 `192.168.x.x:3099` (맥에서 `ipconfig getifaddr en0`) |
| 밖에서 | Tailscale 주소 `100.x.x.x:3099` |

`http://` 는 빼도 붙여 준다. 저장하면 그 주소를 실제로 찔러 보고 **사무실에 몇 명 있는지**
보여준다 — 못 닿으면 이유를 알려주되 주소는 저장한다(맥이 그저 꺼져 있을 수도 있다).
나중에 주소를 고치려면 **사무실 → 서버 설정**(`Ctrl+,`).

토큰 칸을 **반드시 채운다.** 맥 밖에서 붙는 순간(같은 공유기든 Tailscale이든) 백엔드가
토큰을 요구한다 — 맥에서 `.env` 의 `CONSOLE_REMOTE_TOKEN` 에 넣은 값과 같아야 한다.
비워 두면 화면이 텅 빈 채로 열리거나 "못 닿았다" 로 보인다(실제로는 403·401).

맥에서 직접 띄울 때(`127.0.0.1`)는 토큰 없이도 열린다 — 같은 머신은 그대로 통과시킨다.

### 평면도는 빌드에 동봉된다

`layout-*.json` 을 앱 안에 넣어 내보낸다. 좌석 배치의 입력은 백엔드 코드의
`AGENT_REGISTRY`(에이전트 목록 상수)라, 평면도가 바뀌는 계기는 "그 목록이 바뀔 때" =
어차피 앱을 다시 만드는 때다. 서버에서 받아오게 만들면 코드만 늘고 **맥에서 평면도를 뽑는
수동 절차는 그대로 남는다.**

앱이 옛 평면도를 들고 있는데 백엔드에 사람이 늘면 그 사람은 자리를 못 찾는다. 그때는 상태
줄이 붉게 바뀌며 **누가 자리를 못 찾았는지 이름을 찍는다** — 자리 없는 사람은 화면에서
오류 없이 사라지므로, 그 표시가 없으면 아무도 모른다.

### 알아 둘 것

- 설치본은 **x64** 로 고정해 만든다(`build.win.target[].arch`). 맥에서 그냥 빌드하면 호스트를
  따라 **ARM64 가 나오고 일반 윈도우 PC 에서는 설치가 안 된다.** Windows on ARM 은 x64 를
  에뮬레이션하므로 x64 하나로 두 경우를 덮는다.
- 코드 서명을 하지 않아 설치할 때 **"알 수 없는 게시자"** 경고가 뜬다. 개인용이라 그대로 쓴다.
- 맥이 켜져 있고 백엔드(3099)가 떠 있어야 한다. 앱은 화면만 그린다.
- `pnpm start` 가 `ELECTRON_RUN_AS_NODE` 를 지우고 electron 을 부르는 이유는, 그 환경변수가
  붙어 있으면 electron 이 **창 없는 순수 Node 로 떠** `require("electron")` 이 빈 값을 준다.
  에디터의 통합 터미널에서 물려받는 경우가 있어 스크립트에서 끊어 둔다.

### 눈으로 확인하기

```bash
pnpm capture   # 사무실을 한 판 그려 /tmp/idaeri-office.png 로 저장하고 끝난다
```

맥 앱의 `--render`, 웹의 `?static=1` 과 같은 자리다. 다 그리지 못하면 **exit 1** 로 끊고 상태
줄을 함께 찍는다 — 스프라이트 경로가 어긋나거나 스냅샷을 못 받으면 창이 조용히 비는데,
그걸 성공으로 넘기지 않기 위한 입구다.

## 확인용 입구

| URL | 무엇 |
|---|---|
| `?static=1` | 한 판만 그리고 멈춘다. 화면 캡처 도구용 — 실시간 스트림을 열면 페이지가 "다 실렸다"에 도달하지 않아 캡처가 영영 기다린다 |
| `?hour=12` | 창밖 빛을 그 시각으로 고정. 맥 앱의 `--render --hour` 와 같은 화면을 만든다 |
| `?walk=3` | 산책을 강제로 일으키고 그 초만큼 진행시킨 뒤 그린다. 걷기는 시간이 지나야 나타나 정지 화면에 안 잡힌다 |
| `?commute=3` | 출퇴근 걷기를 일으키고 그 초만큼 진행시킨다. `hour` 가 근무 시간이면 출근, 아니면 퇴근. 출퇴근은 **시각 경계를 넘는 순간에만** 일어나 고정 시각 화면에는 영영 안 나타난다 |
| `?renderer=3d` | three.js 3D 화면으로 그린다(시험 단계, 기본은 2D). 아래 「3D 화면」 참조 |
| `?room=<부서>` | 3D 에서 그 방으로 확대한 채 연다(`planning`·`quality`·`evaluation`·`treasury`·`content`·`internalOps`) |
| `?motion=1` | 실패 자세·접수 대기 점·거절·완료 튀어오름·인계를 앞쪽 좌석 여섯 명에게 하나씩 일으킨다(3D). 뒤의 넷은 맥 앱이 밀어 줘야만 일어나 이 입구 없이는 브라우저·캡처에서 한 번도 안 뜬다. 누가 무엇을 맡았는지는 `data-motion-report` |
| `?meeting=1` | 회의 지시(일일 평가 회의 — 회고·PO·임팩트·평가 넷)를 흘려 전원이 회의 자리에 선 뒤 그 초만큼 더 진행시킨다(3D). `?meeting=16` 처럼 머무는 시간(9초)보다 길게 주면 흩어져 자리로 돌아간 뒤를 그린다. 회의는 맥 앱이 `intent` 로 밀어 줘야만 열려 이 입구 없이는 안 뜬다. 보고는 `data-meeting-report` |
| `?chatter=1` | 쉬는 사람을 배회 목적지마다 하나씩 세워 도착 대사(혼잣말·마주친 두 사람의 대화)를 한꺼번에 띄운다(맥 `--chatter-demo`). 대화는 둘이 동시에 2칸 안에 멈춰야 생겨 정지 화면에 우연히는 안 잡힌다. 보고는 `data-chatter-report` |
| `?pressure=3` | 승인 카드 하나를 그 단계(1 줄 · 2 서류 · 3 발 구르기 · 4 대표 경고등)까지 방치된 것으로 꾸며 넣는다. 실 백엔드는 승인 대기가 0건인 날이 대부분이라 이 입구 없이는 네 표현이 한 번도 안 뜬다 |

`hour` 는 같은 이름이 여럿이면 **마지막 것**을 쓴다 — 캡처가 `hour=12` 를 먼저 붙이므로 `--query=hour=19` 로 덮어쓸 수 있다.

걷기·출퇴근 화면은 `data-walk-report` · `data-commute-report` 로 **누가 어디에 섰는지**를 함께
남긴다. 그림만 보면 걷기가 통째로 빠져도 "다들 자리에 앉아 있는 정상 화면" 과 구별되지 않는다.

맥 앱과 대조하려면 두 화면을 같은 크기로 맞춘다 — 캔버스는 창에서 가로 24px·세로 52px 을
뺀 크기이므로, `--size 1400x820` 에 맞추려면 브라우저 창을 1424×872 로 연다.

## 3D 화면 (시험)

2D 와 같은 평면도·같은 움직임(`live.js`)을 쓰고 **그리는 쪽만** three.js 로 바꾼 것이다. 브라우저는
`?renderer=3d`, 윈도우 앱은 메뉴 「사무실 ▸ 3D 화면 (시험)」(설정 파일의 `renderer`)으로 고른다.
캡처는 `electron . --renderer=3d --capture=<파일>` — 저장된 선택을 이번 실행에서만 덮어쓴다.
`--query=room=planning`(주소에 쿼리 덧붙이기 — 방 확대·`walk` 등), `--window=1107x804`(창 크기)를
함께 줄 수 있다. `?walk=` 보고(누가 어느 가구에 어떤 자세로 섰는지)는 캡처 출력의 `보고:` 줄에 찍힌다.

- **조감 + 방 확대** — 방을 누르면 카메라가 그 방으로 다가가고, `esc`·방 밖 클릭으로 돌아온다.
  사람을 누르면 `office:agent-click`, 대표는 `office:president-click`, 확대가 바뀌면 `office:focus`,
  바닥을 눌러 선택이 풀리면 `office:deselect` 사건을 `window` 에 낸다(맥 앱이 WKWebView 로 얹을 때 받는 자리).
- **이름표** — 전원 늘 띄운다. 일하는 중·승인 대기·실패인 사람은 또렷하게, 나머지는 흐린 판으로
  둬서 활성 신호가 묻히지 않게 한다. 마우스를 올리면 이름 옆에 상태·하는 일까지 보인다.
  회의석처럼 붙어 선 사람들의 판이 서로·문패와 포개지면, 앞에 선 사람 판은 두고 뒤의 판만 가장 가까운
  빈 자리(옆·위)로 비킨다(`three/label-separation.js`). 포개지지 않은 판은 움직이지 않는다.
- **배치 고르기** — 3열·2열 중 무엇을 쓸지 3D 카메라로 실제 담기는 크기를 재서 고른다. 2D 산식
  (`폭/열 · 높이/행`)은 비스듬히 돌린 조감에 안 맞아 세로로 긴 창에서 빈 여백이 커졌다.
- **그림체는 코드가 강제한다** — 색은 `three/style.js` 의 `PALETTE` 이름으로만, 형태는 둥근 상자·
  원기둥·구 도우미로만 조립한다. 외곽선(원본 스프라이트의 또렷함)은 렌더러가 모든 물체에 붙인다.
  가구 하나 = `three/furniture3d/<kind>.js` 파일 하나, 디자인 기준은 원본 `sprites/furn-*.png`.
- **상태가 몸짓으로도 보인다** — 실패한 사람은 고개를 떨구고, 저녁·밤에는 자리에 앉은 사람의 책상에만
  스탠드 불이 켜진다. 쓰레기통 앞 로봇청소기는 주간 기억 청소의 신호다(초록 순회 · 파랑 아직 안 돎 ·
  빨강 8일 넘게 멈춤, 옆의 먼지는 사람 판단을 기다리는 건수). 판정 기준은 평면도의 `metrics` 가 싣고 오므로
  **옛 `layout-*.json` 으로는 청소기가 안 나온다** — 평면도를 다시 뽑는다.
- **배회 대사** — 배회 목적지에 도착하면 한 마디(가구 앞 대사 또는 부서 잡담), 2칸 안에 멈춰 선 배회자가 있으면
  두 마디를 주고받는다. 문구·확률·거리·답 지연은 평면도의 `chatter`(맥 `OfficeChatter.swift`)가 싣고 오고,
  고르는 규칙만 `chatter.js` 에 옮겼다 — 2D·3D·윈도우 모두 같다. 옛 평면도에는 `chatter` 가 없어 말하지 않는다.
- **맥 앱에서만 나오는 연출** — 인계(받는 사람 책상까지 걸어갔다 복귀) · 회의(참석자가 회의 테이블에 모였다 흩어짐 — 자리는
  평면도의 `meetingSeats`, 옛 평면도에는 없어 열리지 않는다) · 거절(좌우 흔들림 + `!`) · 접수 대기 점 ·
  완료 시 튀어오름. 앞의 셋은 앱이 계산한 연출 지시(`intent`)를, 뒤의 둘은 앱의 지시 바가 추적하는 단계
  (`pending`)를 받아 그린다. 윈도우 앱·브라우저는 그 데이터가 없어 나오지 않는다(확인은 `?motion=1`).
- **바뀐 것이 없으면 그리지 않는다** — 앉은 사람은 움직이지 않으므로 사무실은 대부분 멈춘 그림이다.
  상태·말풍선·hover·선택·창 크기가 바뀔 때만 그리고(안전망으로 1초에 한 번), 걷는 사람이 있는 동안은
  30fps 로 그린다(`three/frame-pace.js`). 짧은 몸짓(튀어오름·흔들림)도 그동안만 걷기로 친다. 청소기 순회는
  그리기를 따로 일으키지 않고 이미 그리는 프레임에 얹혀 움직인다. 벽·가구는 재질마다 한 덩어리로 합쳐 그리기 호출을 줄인다
  (`three/static-merge.js`). `draw` 가 읽는 입력을 늘리면 `frameSignature` 에도 넣어야 그 변화가 바로 보인다.

```bash
pnpm check:style                          # 팔레트·크기·벽걸이 규칙
pnpm check:pace                           # 프레임 건너뛰기(멈춤 1fps · 걷기 30fps · 변화는 즉시)
pnpm check:merge                          # 합친 뒤에도 삼각형 수·경계 상자가 그대로인지
pnpm check:labels                         # 이름표 겹침 풀기(회의석 넷·문패 피하기·스친 판은 그대로)
node scripts-check-style.mjs --require-all # + 평면도의 모든 가구가 제 빌더를 가졌는지
pnpm vendor:three                          # three.js 버전을 올린 뒤 vendor/three 를 다시 채운다
```

`character-preview.html`·`furniture-preview.html` 은 캐릭터·가구를 한 줄로 세워 찍는 개발용 페이지다

## 배치 규칙을 여기서 다시 짜지 않는다

좌석이 한 칸이라도 어긋나면 두 화면이 서로 다른 사무실이 된다. 어디에 무엇이 놓이는지는
전부 맥이 계산해 `layout-*.json` 에 싣고(Swift `OfficeLayoutExport`), 이쪽은 받은 좌표를
화면 픽셀로 옮기기만 한다. 배율·바닥 명암·부서색·사람 외형처럼 되계산할 수 없는 값도 같이
실려 온다.

**시각 경계도 마찬가지다.** 언제 출근하고 언제 퇴근하는지(조기 출근 5시 · 출근 9시 · 퇴근
21시 · 점심 12시)는 맥이 `attendanceHours` 로 실어 보낸다. 판정 자체는 이쪽이 한다 — 백엔드가
시각을 판정하면 `?hour=` 로 시각을 바꿔 그리는 확인이 통째로 죽는다. 옮겨 적는 것은 **경계
숫자가 아니라 규칙**이고, 숫자를 여기 다시 쓰면 두 화면의 인구가 그 시각에서만 갈린다.

여기 남은 산술은 **타일 크기에 딸린 것들뿐**이다 — 이름표 크기와 문패 높이는 창 크기가
정해지기 전에는 값이 나오지 않아 내보낼 수가 없다. 그 계산에 쓰는 상수는 전부 `metrics`
에서 읽어 맥 앱과 같은 숫자를 본다.

## 파일

- `office.js` — 2D 그리기 전부(바닥·벽·창문·가구·사람·라벨). 색 치환도 여기
- `three/` — 3D 그리기. `renderer3d.js`(장면·카메라·입력) · `overlay3d.js`(글자 겹침층) ·
  `character.js`(직원) · `style.js`(그림체 규칙) · `furniture3d/`(가구 빌더) ·
  `frame-pace.js`(언제 다시 그릴지) · `static-merge.js`(멈춘 물체 합치기)
- `vendor/three/` — 동봉한 three.js(번들러가 없어 `index.html` 의 import map 이 이리로 잇는다)
- `live.js` — 백엔드에서 상태를 받아 오고 사람을 걷게 한다
- `chatter.js` — 배회 대사를 고르는 규칙(맥 `OfficeChatter.swift` 와 같은 씨앗·확률)
- `serve.py` — 브라우저로 볼 때 쓰는 개발용 서버. 백엔드가 CORS 를 열지 않아 프록시가 필요하다
- `main.js` — 윈도우 앱의 껍데기. 서버 주소를 기억하고, 창과 같은 출처로 백엔드를 넘겨준다
- `setup.html` — 첫 실행 설정 화면(서버 주소·토큰)
- `package.json` — Electron 포장 설정. `build` 항목이 어느 파일을 설치본에 넣을지 정한다
- `sprites` — 맥 앱 리소스로 가는 심볼릭 링크(에셋을 복사하지 않는다). 설치본에는
  `extraResources` 로 실제 파일이 복사된다
